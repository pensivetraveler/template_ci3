# 템플릿 감사 단계

template_ci3 는 수정할 때마다가 아니라 **정해진 단계에서** 외부 감사(ai-collab ② 감사 채널)를 받는다(2026-11-09 사용자 결정). 이 문서가 그 단계를 정한다. ai-collab `ai-collab-structure.md` §8 "빌더 경로" 2단계가 이 문서를 가리킨다.

## 1. 단계 = 태그 `v3.N`

- 한 단계는 **감사를 통과한 커밋에 붙인 태그** `v3.N` 이다. 첫 단계는 `v3.0`(템플릿 전체), 그 뒤는 `v3.1`, `v3.2` … (앞 태그 이후의 변경).
- 태그는 감사가 끝난 뒤(재감사 종료 기준을 채운 뒤) 그 마지막 커밋에 단다. 감사 전에는 태그를 달지 않는다 — 태그가 있으면 통과한 단계다.
- 파생 프로젝트의 **기반 커밋이 감사를 통과한 단계 안**이라는 것은 기반 커밋이 어떤 `v3.N` 태그 커밋이거나, 그 태그 뒤에 문서(`docs/`, `README.md`)만 바뀐 커밋이라는 뜻이다. 태그 뒤 코드 변경을 받은 프로젝트는 그 변경에 기대는 부분을 설계 공격에서 줄이지 않는다.

## 2. 언제 감사하나

아래 중 하나가 되면 "안녕 빌더 프로젝트" 세션이 다음 단계 감사를 시작한다.

| 계기 | 이유 |
|---|---|
| 새 빌더 프로젝트를 만들기 전, 마지막 태그 뒤에 코드 변경이 있을 때 | 새 프로젝트가 감사 받은 기반에서 시작하게 |
| 파생 프로젝트가 템플릿 변경을 받아 **운영에 배포하기 전** | 고객 서버로 가는 템플릿 코드는 감사를 거치게 |
| 마지막 태그 뒤 코드 변경이 한 번에 검토할 수 있는 크기에 가까워졌을 때(대략 코드 diff 1,500줄, 라이브러리·생성 파일 제외) | 큰 diff 하나를 감사한 것으로 치지 않는다(ai-collab §4 "검토할 수 있는 크기") |

단계 사이에도 인증·권한·업로드·보안 헤더처럼 위험이 큰 변경은 묻지 않고 감사를 더 받을 수 있다(ai-collab §4 "추가 감사"). 그 감사는 단계를 만들지 않는다 — 다음 태그 감사의 범위에 그대로 들어간다.

## 3. 무엇을 감사하나

- 대상: 앞 태그 이후의 diff(`git diff v3.<N-1>..<후보 커밋>`). 첫 단계 `v3.0`은 템플릿 전체라 한 번에 볼 수 없으므로 아래 영역으로 나눠 따로 감사하고, 모두 끝나면 태그를 단다.
  1. 인증·세션·권한(로그인, 설치 화면, 메뉴 권한, API 인증)
  2. 입력 처리·검증·DB(빌더 API CRUD, Form_validation, 모델)
  3. 파일 업로드·다운로드·저장소(S3, 비공개 파일)
  4. 보안 헤더·CSP·출력(XSS, 뷰)
  5. 빌더 화면 스크립트(`public/assets/builder/js`)
- 종류: 의도 불일치 점검(`docs/builder/` 와 다르게 동작하는 곳) + 보안 검토. 템플릿은 인증·권한·입력 처리를 담고 모든 파생 프로젝트로 퍼지므로 **위험이 큰 대상**으로 보고 Astra 와 Fable 둘 다 쓴다.
- 재감사·종료 기준, 남은 지적 처리는 ai-collab §4 를 그대로 따른다.

## 4. 기록과 알림

- 감사마다 아래 표에 한 줄을 적는다. 남은 high 는 `해결`·`차단`·`위험 수용`(사용자 결정) 중 실제 상태로 적는다.
- 태그를 달면 ai-collab("Collab 기능 보강")에 `[안내]`로 알린다: 태그, 커밋, 범위, 남은 high 상태. ai-collab 은 `docs/projects.md` 와 빌더 프로젝트 2단계 판단에 쓴다.
- 새 프로젝트는 가장 최근 태그에서 시작하는 것을 기본으로 한다(`docs/new-project.md` 1).
