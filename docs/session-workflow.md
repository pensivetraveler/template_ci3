# 템플릿 개발: 상위 세션과 이슈별 하위 세션

template_ci3 개발은 **상위 세션 "안녕 빌더 프로젝트"**가 통합·형상 관리를 맡고, 이슈마다 **하위 세션**이 개발한다(2026-11-13 사용자 결정).
- 하위 세션은 자기 브랜치에만 커밋한다.
- 상위 세션만 v3 에 합치고 push 한다.

## 1. 역할

| | 상위 세션 ("안녕 빌더 프로젝트") | 하위 세션 (이슈 하나) |
|---|---|---|
| 작업 위치 | 원래 체크아웃 `~/Programming/Projects/template_ci3` (v3) | 작업 트리 `.claude/worktrees/<이슈>` (브랜치 `issue/<이슈>`) |
| 하는 일 | 요청 접수·이슈 나누기, 하위 브랜치 검토·합치기, 시험, push, 요청 세션 회신, 대시보드, 감사 단계 | 이슈 하나 구현, lint·시험, 자기 브랜치에 커밋, 상위 세션에 통합 요청 |
| 하지 않는 일 | — | v3·main 에 커밋·merge·push, 원래 체크아웃 수정, 다른 이슈 브랜치 수정, 요청한 세션에 최종 회신(커밋 해시는 합친 뒤 정해짐) |

다른 세션의 `[요청]` 은 지금처럼 상위 세션이 받는다. 상위 세션은 요청마다 둘 중 하나로 정한다.
- 작은 것은 직접 처리한다.
- 나머지는 이슈로 나눠, 사용자가 만든 하위 세션에 맡긴다.

## 2. 이슈 이름

- 이슈 번호는 대시보드 항목 번호를 쓴다: `template-ci3-N` → 이슈 `빌더-N`.
- 하위 세션 이름은 `#빌더-N <요약>`, 작업 트리는 `.claude/worktrees/빌더-N`, 브랜치는 `issue/빌더-N`.

## 3. 하위 세션 절차

1. **작업 트리 만들기**: 원래 체크아웃에서 `scripts/worktree-setup.sh 빌더-N`을 실행한다.
   - v3 최신에서 브랜치를 만들고 의존 파일을 잇는다.
   - 이미 만든 작업 트리 안에서는 인자 없이 실행한다.
   - 그 뒤 모든 명령은 작업 트리 안에서 한다.
2. **구현**: 요청으로 거슬러 올라가는 줄만 바꾼다. 결함 수정에는 회귀 시험을 넣고, 수정을 되돌리면 그 시험이 실패하는 것까지 본다.
3. **확인**: `npm run lint`, `scripts/test.sh all`.
   - 시험 DB·포트가 하나라 여러 작업 트리의 시험은 차례로 돈다. 기다림 메시지가 나오면 그대로 둔다.
   - 브라우저 확인은 원래 체크아웃(localhost:8080)만 보이므로, 필요하면 통합 요청에 "브라우저 확인 필요"로 적는다.
4. **커밋**: 자기 브랜치에, 파일을 하나씩 지정해서(`git add <파일>`) 커밋한다. 커밋 메시지 끝에 요청 번호(`bizsoft 요청 #bizsoft-N` 등)와 Co-Authored-By 줄을 적는다.
5. **통합 요청**: 상위 세션에 아래 양식으로 보낸다. 상위 세션이 합칠 때까지 브랜치를 그대로 둔다(고칠 것이 있으면 상위 세션이 알린다).

```
[통합 요청 #빌더-N] <한 줄 요약>
- 브랜치: issue/빌더-N (커밋 <해시> …, v3 <기준 커밋> 기준)
- 바꾼 것: <파일·이유>
- 확인: lint / test.sh all 결과, 되돌려 실패를 본 시험
- 확인 못 한 것: <브라우저·운영 등>
- 회신할 곳: <요청한 세션 이름과 요청 번호, 없으면 없음>
```

stash 는 작업 트리끼리 같이 쓰므로 맨 `git stash`/`git stash pop`을 쓰지 않는다. 잠깐 치울 때는 임시 커밋을 쓴다.

## 4. 상위 세션 절차 (통합)

1. **검토**: `git log v3..issue/빌더-N`, `git diff v3...issue/빌더-N`. 요청과 상관없는 변경, 빠진 시험, 템플릿 원칙(설정 키 지우지 않기 등)을 본다. 고칠 것이 있으면 하위 세션에 돌려보낸다.
2. **기준 맞추기**: v3 가 그 사이 앞서 갔으면 하위 세션의 작업 트리에서 `git -C .claude/worktrees/빌더-N rebase v3` 를 실행한다(충돌은 하위 세션에 맡겨도 된다).
3. **합치기**: 원래 체크아웃에서 `git merge --ff-only issue/빌더-N` 한다. 이력은 일자로 유지한다.
4. **시험**: `npm run lint`, `scripts/test.sh all`. 필요하면 브라우저로 확인한다.
5. **push**: `git push origin v3`.
6. **회신**:
   - 하위 세션에 합친 커밋을 알린다.
   - 요청한 세션에 `[회신 #…]`(합친 커밋, 받는 쪽 할 일, 확인 못 한 것)을 보낸다.
   - 대시보드 항목을 닫는다.
7. **정리**: 하위 세션이 끝났다고 하면 `git worktree remove .claude/worktrees/빌더-N` 과 `git branch -d issue/빌더-N` 을 한다.

## 5. 작업 트리와 시험 서버

- 컨테이너(`template-ci3-web-1`)는 원래 체크아웃을 `/var/www/html` 로 마운트한다. 작업 트리는 그 아래 `.claude/worktrees/<이슈>` 로 보인다. 그래서 작업 트리는 반드시 원래 체크아웃의 `.claude/worktrees/` 아래에 만든다.
- `scripts/test.sh` 는 실행한 작업 트리의 코드로 시험한다. 잠금(`/tmp/template_ci3_test.lock`)으로 한 번에 하나만 돈다.
- `scripts/worktree-setup.sh` 는 커밋하지 않는 `vendor`·`.dev-vendor`·`node_modules`·`.env.development` 를 원래 체크아웃에 상대 경로 링크로 잇는다. 호스트와 컨테이너 양쪽에서 같은 곳을 가리킨다. 의존성을 바꾸는 이슈(composer·npm)는 상위 세션과 먼저 정한다.
